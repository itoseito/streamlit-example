# 自動制作の手順（毎日2本）

毎日決まった時刻に新しいセッションが立ち上がり、この手順で本編2本と、それぞれのショート1本を作る。公開はしない（アップロードはユーザーが行う）。

1. ブランチ `claude/two-minute-rule-video-tdb81r` を取得して最新にする。`CLAUDE.md` と `trylog/README.md` を読む。
2. 準備：`trylog/setup_voice.sh` が要る場合は実行（VOICEVOXは予備）。`pip install msgpack httpx`。声は `trylog/voice_ref/` の本人の録音を見本に、Fish Audio で作る（キーは環境の安全な保存先にあり、通信の途中で付く。ファイルにもチャットにも書かない）。
3. `trylog/QUEUE.md` の上から「未着手」を2つ選ぶ。
4. それぞれについて：
   - 一次資料の本文を取得して全文読む。読めなければ「保留：理由」にして次へ。
   - `trylog/make_08_10.py` を手本に、新しい `timeline.json` を作る（2分半・早口・起承転結・場面の型は `kit_scenes.js`）。
     必ず入れる：冒頭の共感 →「AI生成・架空の人物」の明示 → 約束 → 出典 → 図解 → 正直な限界 → コメントの問いかけ → 締め。
     著者の主張と、TRY LOGの例・見立ては、画面右上の表示（src）で分ける。作った体験談や成果、収入の約束は入れない。
   - `python3 voice_fish.py <動画>`（音声認識の照合で「要確認」が出た場面は、言い方を変えて作り直す）
   - 全場面の静止画を撮って、文字のはみ出し・重なり・空白がないか見る。
   - `./render_one.sh <動画>`、`node thumb.js <動画>`（サムネは先を行く人＝外国人の3人のだれか、`"style": "b"`、文字は8文字以内）、`python3 make_docs.py <動画> <章の場面番号>`
   - `SOURCES.md`（原文との対応表と、確認できていない点）と `POSTING.md`（タイトル、説明欄、章、タグ、固定コメント、公開時のチェック）を書く。
   - ショート：`python3 make_short.py <動画> <見せ場の場面番号> "<続きが気になる一言>。続きは、本編で。"` → `python3 voice_fish.py <動画>_short` → `python3 build.py <動画>_short --bgm`
5. `QUEUE.md` を更新し、コミットしてプッシュする。
6. 最後に、作った2本の「タイトル・長さ・確認できていない点・気になった点」を短くまとめて報告する。

止まる条件：Fish Audio の声が作れない、一次資料が読めない、書き出しが失敗する。そのときは無理に作らず、何が止まったかを報告する。
クレジットを使うサービス（Higgsfield など）は使わない。
